### 关键 bug 修复
stat_card count_up 动画调试中发现两个递归问题：
1. count_up 内部 var.set() 触发 trace → trace 再调 count_up → 动画被反复重启
   → 用 _animating 标志位防止递归
2. trace 触发时 var 已被设成 target，从 var.get() 起步会从 100→100（瞬时跳）
   → 引入 from_value 参数，stat_card 维护 displayed['v'] 状态

## 封装：数字签名 + 版本 + 安装包

### 需求
用户要求打包时加入数字签名（签名者=程震宇）、版本 1.0，并可生成安装包。

### 新增文件
- `version_info.txt`：PyInstaller 版本资源（作者/公司=程震宇，v1.0.0.0）。
  ⚠️ 必须是一个返回 `VSVersionInfo(...)` 的纯表达式——PyInstaller 用 `eval()` 直接求值，
  不能写 `import`、也不能写 `version_info = `（赋值不是合法 eval 表达式）。
- `sign_exe.py`：Authenticode 签名工具。默认用 PowerShell 生成 CN=程震宇 的自签名证书
  并签名；设 `SIGN_PFX`/`SIGN_PWD` 则用正规 CA 证书。用 `signtool`（Windows SDK，优先 x64 避开 arm）。
- `build.py`：一键 打包 → 签名（`PyInstaller.__main__.run` + `sign_exe`）。
- `installer.iss`：Inno Setup 安装脚本（本机无 iscc，待用户装 Inno Setup 后 `ISCC installer.iss` 编译）。

### spec 改动
- `综测核算程序.spec` 的 EXE 增加 `version=os.path.join(HERE,'version_info.txt')`。

### 验证（已实跑通过）
- `python build.py` 退出码 0；产物 `dist/综测核算程序.exe`（~20MB）。
- 版本资源读取：FileVersion/ProductVersion=1.0.0.0，Company=程震宇，Copyright=© 程震宇。
- 签名：HASSIG=True，SignerCertificate.Subject=CN=程震宇；
  自签名证书 Status=UnknownError 仅因根证书不受信任（"在不受信任提供程序信任的根证书中终止"），
  属正常，非签名无效。换正规 CA 证书即受信任。
- 已签名 exe 跑 `--selftest` 退出码 0（功能不受影响）。

### 踩坑
1. `find_signtool` 最初 `os.walk` 误选 arm 版 signtool → WinError 216 版本不兼容；
   已改为优先 x64 / x86、排除 arm。
2. 自签名证书导出后若从个人证书库移除，PowerShell `Get-AuthenticodeSignature`
   会因找不到签名者证书而 Status=UnknownError；改为保留证书在 `Cert:\CurrentUser\My`。
3. PowerShell 中文（程震宇）以 GBK 输出导致 Python utf-8 解码崩溃；已在 `_run_powershell`
   中强制 `[Console]::OutputEncoding = UTF8` 并安全解码。
